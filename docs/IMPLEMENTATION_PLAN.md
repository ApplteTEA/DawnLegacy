## 3. 단계별 개발 계획 — 의존성/담당/완료 조건

### Phase 0 — 기획 기준선·데이터 인벤토리
- 담당: High. 신규 코드 전 작업.
- 작업: 기존 저장 상태/게임 로직/폼/타입 17종/포켓몬 DB/진화표/라이벌 회차 데이터 인벤토리. 사용자 확정·제안 구분/결정 기록. 6개 마스터 문서 링크와 이벤트 ID 검증.
- 산출: GAME_DESIGN 최신화, 플레이 가능한 시나리오 0~12장, 경로·게이트 테이블, 사양 백로그.
- 완료: 승인할 신규 설정이 빠짐없이 표로 나타나며, 확정 규칙 변경 0건.

### Phase 1 — Work 필드·이동·충돌 작업 통합 (최우선 의존성)
- 담당: Work(대기 중), High는 리뷰/테스트·병합.
- 작업: DL-001~003의 나무/건물/물/NPC 충돌, 순간이동·카메라 버그, 픽셀아트 타일 개선. **기존 Work 요청 범위를 삭제하거나 대체하지 않는다.**
- 핵심 인계: Work는 재개 시 최신 `main`과 **모든 MD**를 다시 읽고, 최근 High 작업인 시온 4회 대결/저장, 새 게임 초기화 방어, 이름표/HUD를 병합.
- 완료: 렌더러와 충돌 판정이 동일 지형 데이터를 참조, 이동/재접속/동행·모바일 버튼 회귀 검사, 다중 맵 구현 가능한 구조 확립.
- 실패 시: Phase 2의 새 멀티맵 제작은 착수 가능하지만 이동/맵 통합 릴리즈는 보류.

### Phase 2 — 저장 스키마 v3 + 맵 기반 엔진
- 담당: High(구현), Work(정밀 검토).
- 작업: `mapId`/로컬 위치/포털/스폰/충돌/지역 인카운터 데이터. `s.x/y` 기존 세이브의 이관 테이블. 맵 정보와 NPC 배치/이벤트를 소스에서 분리.
- 데이터 계약: WORLD_MAP의 Map ID 불변, 출입구 왕복/안전 스폰 검사, 포획·일반 배틀·센터가 새 맵에서 동일하게 작동.
- 세이브 마이그레이션 예: 기존 0≤x<20 → M00, 20≤x<40 → D01, 40≤x<60 → R04, 60≤x<80 → R03 근처, 80≤x<100 → R07 근처 **안전 스폰**. 역사적으로 방문한 지역/스토리의 정확한 변환이 불가능하므로, '이관 최초 실행' 안내와 별도 복구 백업을 제공. 이 예시는 사용자 승인/Work 결과 전 확정 아님.
- 완료: old-save + fresh-save 모두 시작/회복/이동/저장 가능, 원위치 불가 지역에서는 명시된 안전 스폰/안내, 구형 라이벌 데이터 유지.
- **금지:** 마이그레이션 중 구형 게임 저장 키를 즉시 삭제하거나 유저에게 새 게임을 강요.

### Phase 3 — 이벤트/퀘스트·컷신 런타임
- 담당: High.
- 작업: `eventFlags`, `rewardClaims`, `questStates`, `cutsceneSeen` 데이터 모델. 대화/보상/승리/패배/중단·스킵 공통 시스템. 월드 포털 게이트와 퀘스트 저널/HUD.
- 이벤트는 `STORY_EVENTS.md`의 ID/의존성을 데이터 테이블로 변환. 새로운 이벤트에 대한 자동 검증(플래그 중복, 존재하지 않는 맵, 순환 의존성, 재시도 불가).
- 완료: 최소 샘플 EV_00/EV_04/GYM_01에서 중복 보상·컷신 재진입·전투 패배·브라우저 재접속·오프스크린 NPC 문제 없음.

### Phase 4 — 수직 슬라이스 (새벽마을 → G1 → 이슬숲)
- 담당: High, 디테일 Work.
- 제작: M00/R01/M01/D01, NPC/상점/체육관 퍼즐, G1 보상, 숲 구조/금속 고리, 시온 1차전, 타입별 첫 스타팅/이로치 출전 테스트.
- 산출: 실제 아트/대사/맵/이벤트/퀘스트/4방향 필드 스프라이트/저장·복구가 포함된 60–90분 플레이 구간.
- 완료 기준: 17타입 각각 G1 클리어 가능한 경로가 있고, 막힌 출입구는 반드시 필요 조건 표시; 오래된 세이브 복원과 390×844 브라우저 검증 통과.
- **Go/No-go:** 이 수직 슬라이스의 조작성·저장 안정성이 확보되기 전 도시 2~8을 병렬로 대량 생성하지 않는다.

### Phase 5 — 2·3·4관장 + 미스터리 1~2막
- 지도: R02/M02/D02/F01, R03/M03/D03, R04/M04/D04/F02.
- 시나리오: 항구 빈 화물·도겸, 발전소/세라, 유적·여명석. 라이벌 2·3차전.
- 시스템: 배지 2–4, 기술머신/기술 교체, 복합 타입 상성, 레벨 40 대비 경험치 조정, 컷신·지도·회복 강화.
- 완료: 각 도시의 입장/관장/단서/다음 출구/재방문 대사, 저장/회복/도주 및 권리 점검.

### Phase 6 — 5·6·7·8관장 + 이클립스단 본편
- 지도: R05/M05/D05, R06/M06/D06, R07/M07/D07, R08/M08/D08.
- 시나리오: 홍염 실험, 설산의 진실, 철벽 본거지, 최종 배지. 라이벌 4·5차전, 서브퀘스트 07–10.
- 데이터: 기존 DB에 없는 진화종/타입/에셋을 합법적으로 확보하거나 오리지널에셋을 제작, 각 관장의 마지막 포켓몬 및 스킬셋 검증.
- 완료: 체육관8 각각의 개별 승리 플래그, 보상 1회, 스토리 3~4막 완료, 도로 경로 및 세이브 복구 통과.

### Phase 7 — 일식·아르세우스·리그·엔딩
- 지도: D09/R09/M09/L01.
- 스토리: 공명선 3곳을 순서대로 분리, 카이론/공명수호기 전투, 아르세우스의 비포획 시련, 빛 복구, 챔피언로드 시온 6차전.

## 4. 저장 데이터 마이그레이션 및 호환 원칙
### 기존 데이터 스키마(현재 코드)
- Key `dawnLegacyCompleteV2`, `version:1`, `type`, `x/y/face`, `party`, `box`, `balls/great/potions`, `money`, `badges`, `defeated`, `dex`, `steps`, `wins`, `champion`, `playSeconds`, `rival`, `followerTrail/fieldFollower`.
- 기존 새 게임 초기화 버그는 `resetInProgress` 차단을 가진 최신 코드 기준으로 보존.
- 4회 라이벌전 승리 플래그: `시온`, `시온 2차전`, `시온 3차전`, `시온 4차전`. 코드에서는 이 값들이 실제 `s.defeated`에 기록됨.

### 이관 전략 (제안)
1. 로딩 직전 원본 세이브 파싱/기본 타입 검사. 읽지 못하면 원본을 보존하고 신규 시작 제안.
2. 원본 백업 키 생성 및 스키마 버전 기록. 완료 실패 시 원본으로 롤백.
3. 지도/스폰 새 필드 추가. 구형 위치를 새 지도 안전 스폰으로 매핑, 실제 좌표가 재구성되지 않으면 경고 및 복구 센터 제공.
4. `s.badges` 숫자는 구형 프로토타입 획득 이력으로 저장. **새 정식 배지 1~8 수여로 자동 변환하지 않는다.** 혼동 방지로 `legacyBadgeCount`와 `progress.gymWins` 분리.
5. `s.defeated`의 구형 NPC/라이벌 기록은 보존. 새 `progress.rivalRounds`는 오직 명시한 사용자 동의 기준에 따라 이전 기록을 연결; 처음 접속 시 신규 8배지 이벤트 완료로 조용히 변환하지 않는다.
6. `s.rival.type/starter/support` 보존; 지원 3종이 미존재하면 기존 deterministic 생성 방식 1회만 호출. 6마리 최종 팀을 위한 추가 슬롯은 저장한 뒤 재추첨 금지.
7. `eventFlags/rewardClaims/cutsceneSeen` 기본 빈 객체 생성, 스토리 필수 이벤트는 신규 지도에서 처음 만나도록 설정.
8. 새 `saveVersion` 반영 후 검증/저장, 백업은 삭제하지 않음. 마이그레이션 두 번 실행해도 결과가 같은지(idempotency) 검사.

**중요:** 아이템·도감·레벨·이로치·포획 성과는 유지. 이전 프로토타입의 챔피언 칭호는 별도 기념 기록으로 남기고 8배지 최종 엔딩을 이미 본 것으로 설정하지 않는다.

## 7. AI 간 작업 운영·원자적 인계
- **High:** 신규 시스템/맵/콘텐츠 구현 및 자동 회귀. 작은 커밋 단위로 진행, `TODO.md`, `PROJECT_STATUS.md`, `CHANGELOG.md` 갱신.

- **완료 인계 필수 값:** 작업 범위, 전·후 커밋 SHA, 수정 파일, 테스트 환경, 미구현/미검증, 신규 설정 승인 ID, 다음 단계의 명시적 의존성.
