# 기술 구조 및 개발 인계

기준: 2026-11-03 저장소 기본 브랜치 파일 존재 확인. 세부 함수 구조는 후속 코드 검토 필요.

## 웹 실행 흐름
1. index.html: Canvas, HUD, 모바일 방향키/액션 UI
2. bootstrap.js: CSS와 world-v2.js를 로드하고 game.js 실행
3. world-v2.js: 필드 타일/엔티티/주인공/NPC/동행 포켓몬 렌더링
4. game.js: 포켓몬 DB, 게임 상태, 이동, 전투, 이벤트 등
5. style.css / battle-v2.css: 화면 스타일

## 설계 원칙
- 렌더링, 게임 상태, 이벤트 진행, 데이터 정의를 가능한 한 분리
- 방향 상태와 이동 프레임은 데이터로 전달하고, 렌더러는 정해진 스프라이트를 그림
- 포켓몬 종류별 필드 스프라이트는 명시적 에셋 매핑 및 오류 처리를 사용
- 라이벌 스타팅은 **최초 생성 시 결정하고 세이브에 보존**. 로딩 때 재추첨 금지
- 이벤트 진행 플래그는 중복 실행되지 않도록 저장
- 저장 구조를 바꿀 때 구버전 세이브 마이그레이션 제공
- 모바일 Canvas 해상도/스케일/픽셀 보간을 일관되게 처리

## 아직 확인할 것
- Work가 재구축한 실제 그래픽 아키텍처와 에셋 경로
- 기존 세이브 키/버전과 필드 이벤트 저장 방식
- 배틀/진화/타입 상성 구현 세부
- 자동 테스트/빌드/배포 파이프라인

Work 결과가 반영되면 이 문서를 실제 파일/함수/데이터 구조에 맞게 갱신한다.
