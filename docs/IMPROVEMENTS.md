## 관리 방식

각 작업은 `DL-###` 고유 ID, 중요도(P0~P3), 담당(High/Work), 상태, 재현 방법, 관련 파일, 완료 기준과 검증 증거를 가진다.
- 상태: 제안 / 대기 / 진행 중 / 구현 완료(검증 대기) / 검증 완료 / 종료 / 차단됨 / 재발.
- 사용량 제한으로 시작하지 못한 Work 작업은 `대기(Work 사용량 제한)`.
- 완료 시 근거가 되는 커밋, 테스트, 실제 실행 환경을 기록. 미확인 항목을 완료 처리하지 않는다.
- 연관 과제가 하나의 Work 작업으로 함께 진행되더라도, 항목별로 완료 여부를 판단한다.

### DL-005 — 새 게임 선택 후 기존 저장이 되살아나는 문제
- **우선순위:** P0
- **담당:** High
- **상태:** 구현 완료(검증 대기)
- **보고:** 새 게임을 시작해도 기존 모험으로 돌아간다는 사용자 보고.
- **확인된 원인:** 기존 메뉴는 `localStorage.removeItem(SAVE)` 직후 `location.reload()`를 호출하지만, `beforeunload` 핸들러는 무조건 `save()`를 수행해 삭제한 데이터를 다시 생성할 수 있음.
- **수정:** `game.js`에 `resetInProgress` 플래그를 추가하고 초기화가 시작된 경우 모든 `save()` 호출을 무시. 삭제 실패 시 재로드를 하지 않음.
- **검증:** `tests/restart-rival-visibility.test.cjs`에서 저장→새 게임 확인→삭제→종료 시 save 호출에도 기존 데이터가 부활하지 않는지 자동 검사. 실제 모바일 브라우저 초기화는 미검증.
- **Work 인계:** 재구축 과정에서 `game.js`의 `save()`, 새 게임 버튼, `beforeunload` 핸들러를 이전 상태로 되돌리지 않도록 주의.

### DL-006 — 라이벌 미표시 및 최신 코드 캐시 불일치

- **담당:** High

- **보고:** 라이벌 위치를 알 수 없고 실제 필드에서도 찾기 어려움.
- **확인된 원인:** `bootstrap.js`가 신규 `game.js`를 로드할 때 2026-11-03의 구 버전 캐시 쿼리를 계속 사용. 별도로 라이벌은 일반 NPC와 스프라이트가 유사하며 이름표가 없었음.
- **수정:** `bootstrap.js`와 `index.html` 캐시 버전 갱신, `game.js`의 `draw()`에서 월드 좌표 기준 NPC 머리 위에 '라이벌 시온' 이름표 표기, 새벽마을 HUD에 위치 안내.
- **검증:** `tests/restart-rival-visibility.test.cjs`에서 모듈 캐시 버전 일치 및 월드 좌표 기반 이름표 렌더링 검증. 실제 사용자 화면은 미검증.
- **Work 인계:** Work가 새 필드 렌더러를 구성할 때 마커 계산식과 NPC 실제 좌표를 검토해 통합할 것. 렌더러 구조를 바꾼다면 이름표가 유지되도록 하고, 별도 에셋을 완성하기 전까지 식별 가능성을 보존.
